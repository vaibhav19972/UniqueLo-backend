# Schema drift — RESOLVED (history)

**Status: closed 2026-10-25.** Kept as the record of what was wrong and how it was fixed.

## What it was

`schema.sql` (bootstrap) and the live catalogue disagreed in both directions:

- **declared** six retired columns: `sold_count`, `batch_number`, `batch_total`,
  `craft_region`, `craft_cluster`, `expression_slug`.
- **lacked** the `20261024` trust/marketplace columns (`style_code`, `attributes`,
  `cod_available`, `country_of_origin`, `return_window_days`, `manufacturer_*`,
  `packed_by`, `delivery_days_*`, `weight_grams`, `hsn_code`, `size_chart`, `fit_notes`,
  `model_*`, `package_*`) and `variants.barcode`.
- `seed.sql` inserted `is_mock`, `vibes`, `moods` — columns no DDL ever created, so a
  fresh `schema.sql` + `seed.sql` build failed at the first product insert.

## What was done (2026-10-25)

1. `schema.sql` products block now equals the **measured live shape**: 44 columns,
   enforced by `scripts/check-schema-parity.mjs` against `contracts/live-columns.txt`.
2. Retired columns removed; trust + marketplace columns mirrored; `variants.barcode` added.
3. **`is_mock` retired by decision** — not in the schema, not in either client. The
   catalogue has no mock flag, so no migration adds it.
4. `seed.sql` demoted to **local/dev legacy** (header note). It is not a production path
   and is expected to lag the schema; its content is intentionally not rewritten.
   Production baseline = `production-seed.sql`, generated by `scripts/gen-seed.mjs` and
   checked by `gen-seed.mjs --check`.

## Guards added

| Guard | Stops |
|---|---|
| `scripts/check-schema-parity.mjs` | `schema.sql` drifting from the measured live column set |
| `scripts/check-contract.mjs` | `data.ts` / Admin generator / `CONTRACT.md` drifting from schema + migrations |
| `scripts/gen-seed.mjs --check` | production seed drifting from `web/src/data/*.json` |

Run all three before touching shared shape.
